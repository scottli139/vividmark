# 脚注（Footnotes）

GFM 扩展语法：正文里写 `[^标识符]` 作引用，任意位置写 `[^标识符]: 内容` 作定义。
渲染时定义集中到文末、按引用首现顺序编号，角标与回链双向跳转。
VividMark 双端支持（WYSIWYG / 预览 / 分屏 / PDF / 站点导出）。

## 基本用法

Markdown 由 John Gruber 于 2004 年创建[^gruber]，目标是「易读易写」[^readable]。
它后来被各方扩展，形成了 CommonMark 与 GFM 等规范[^gfm]。

[^gruber]: John Gruber 与 Aaron Swartz 合作发布了最初的 Markdown 语法说明。
[^readable]: 纯文本形态即可直接阅读，不被标记符号干扰。
[^gfm]: GitHub Flavored Markdown，2017 年起有正式规范，脚注是后续补充的扩展。

## 命名标识符

标识符不限于数字[^note-about-ids]，用有意义的单词更便于维护长文档[^tip-naming]。

[^note-about-ids]: 标识符只用于配对，与最终编号无关——编号永远按引用出现顺序生成。
[^tip-naming]: 移动段落时不必重排数字，这是命名标识符的最大好处。

## 同一脚注被多次引用

同一定义可以在多处引用[^shared]，第二次、第三次引用共享同一编号[^shared]，
文末条目会列出每个引用位置的回链。

[^shared]: 被引用两次的脚注：两条回链分别指回两个引用锚点。

## 多行定义

定义的续行用 4 空格（或一个制表符）缩进[^multiline]。

[^multiline]: 这是定义的第一行。
    这是续行，仍属于同一条脚注。

## 定义中的行内格式

[^rich]: 支持 **加粗**、*斜体*、`行内代码` 与 [链接](https://commonmark.org)。

富文本脚注在此被引用[^rich]。

## 定义位置自由

定义可以写在文档任意位置（比如紧跟引用段落之后），渲染时统一归集到文末。

正文引用了一个就近书写的定义[^nearby]。

[^nearby]: 这条定义写在文档中部，渲染时仍出现在文末脚注区。

继续书写后续段落，不受定义打断。

## 未引用的定义

未被任何引用指向的定义**不会**渲染（与 GitHub 行为一致），但源码原样保留，
WYSIWYG 中可见可编辑——下面这条在预览里看不到：

[^orphan]: 孤立定义：没有引用指向它，预览不渲染，源码不丢失。

## 悬空引用（优雅降级）

没有对应定义的引用保持字面文本，不渲染为角标：[^no-such-def]。

## WYSIWYG 编辑说明

- 引用显示为蓝色角标 `[N]`，编号与预览一致（首现顺序）；定义以 `[^标识符]:`
  挂排块显示，标识符可见，内容直接编辑。
- 删掉某条定义后，其引用退化为 `[^标识符]` 原文形态（灰色），与预览的
  字面文本降级口径一致；撤销删除即恢复编号。
- 保存/切换模式后源码保持 `[^id]` / `[^id]:` 原样（定义位置不归一化）。
